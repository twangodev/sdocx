# Pencil2 vector luminosity mask control

The experimental source patches, harnesses and comparators were retired. The
findings below are historical; native inputs, captures and receipts remain.
These prototype assertions and external-reader measurements are not claimed
as equivalent maintained Rust coverage.

This historical luminosity-mask experiment reused the v195 input, crop provenance and reader versions. It did not change native acquisition.

The SVG writes ordered black translucent unit rectangles. The independently constructed PDF writes the same ordered unit rectangles in white over an opaque black backdrop in an isolated DeviceRGB transparency form, uses the form as a luminosity soft mask, and paints the solid black brush color through that mask. This is a standalone PDF construction, not the sdocx direct PDF exporter. It is tied to the output pixel grid and is not scalable paint. The 2x case is separately sampled at that resolution, not a PDF viewer zoom.

The minimal color control puts three 20% white rectangles over black in the mask, and paints red over an existing opaque blue page. PDFium yields (123, 0, 132, 255), MuPDF (121, 0, 133, 255), against ideal approximately (124, 0, 131, 255). For direct translucent black rectangles on transparent output, PDFium reports only the final rectangle alpha (51), whereas MuPDF gives 122. PDFium on opaque white gives 130 RGB, showing accumulated compositing in that case. This isolates a transparent bitmap rendering behavior in the tested PDFium version; its internal implementation is not established. The single-color mask control does not establish mixed-color, transformed, clipped, or general page parity.

The historical comparison verified exactly 84 RGBA 192 × 192 layer frames per scale (12,386,304 bytes each), and SHA-256 `3c239d4ba13f0fb16a18beefee23b1189524068e505b63127e0f3ba4105336d8` for 1x and `0c9b540784f59e781a0d966e5b75d0eed66ceac6350e95c25a45f7751e0d519f` for 2x. These were generated by the pinned v195 Rust probe, whose input stream hash is checked by the probe. The native data only retain the 62 × 22 crop: the error calculation fills the rest of the frame with zero, relying on the receipt's statement that source frame support was checked within that crop. It does not independently recheck a retained full native frame. The PDF writer is PyMuPDF low-level PDF object/stream construction, not its drawing API or an sdocx writer.

The color control includes transparent, blue, and white backdrops. Its MuPDF samples are premultiplied RGBA; PDFium samples converted through Pillow are straight RGBA. Compare alpha or opaque backdrop pixels directly, not the translucent RGB channels across readers.

The color control also checks two ordered, differently colored mask paints over transparent, blue, and white backdrops. Both paints reuse the same mask containing three 20% white rectangles; the script checks both orders against ideal source-over within five 8-bit premultiplied channel values and asserts the color order is visible. MuPDF returns premultiplied samples; PDFium's straight samples are converted before comparison. The control pins MuPDF 1.28.2 and PDFium 156.0.8076.0 and constructs PDFs in memory. These are synthetic compositing controls, not native colored Pencil2 captures or the sdocx PDF exporter. A single mask painted in one color cannot represent overlapping strokes of different colors; retain their order and separate masks.
