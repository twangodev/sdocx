# Marker3 size-9 counterexamples

Three synthetic tool-1 Model/Drawing captures extend `../marker3-size9-exploratory`. `phase2` and `phase4` use size 9 with different trajectories, pressure and coordinate phase, and native Draw matrices at 2× and 4× respectively. `boundary` uses size 9.0001 at 1×. The capture uses the same retained native Drawing vector bridged into its selected RTV1, with Mesa llvmpipe, as documented by the prior diagnostic; it does not establish Android device or saved-note parity. The 256×256 native frame bounding boxes are respectively [34,41,115,88], [54,57,192,135], and [17,25,72,44], all inside the compared 256×256, 256×256 and 128×128 regions. No native support is clipped by those regions.

`PYTHON=/path/to/python PYTHONPATH=/path/to/pypdfium2 bash tools/marker3-size9-expanded/replay.sh` verifies hashes and input bits, expands the size gate to 9.0001 only in a temporary archive of commit `4361933850036a3c2e5a333814f04b499f47fe6a`, checks the expected geometry counterexample, and compares actual public SVG and direct PDF with the native transparent frame and mathematical #fcfcfc composition. The source input coordinates, pressures, size, zero tilts and orientations, and timestamps are checked against exporter literals. Reader versions and aggregate metrics are pinned; the dependencies and native acquisition limitations are the same as the preceding diagnostic. `capture.py OUTPUT` regenerates native captures using the host-local pinned dependencies. Lockfiles are retained in the preceding diagnostic.

The first independent input yields 12 candidate geometry points versus 37 native Drawing points, so the existing production size guard remains unchanged. Aggregate L1 baseline/profile values for SVG, MuPDF and PDFium are 215951/211257, 279780/275490, 154622/149290 at 2×; 582380/577915, 533738/527887, 416842/409359 at 4×; and 59547/51176, 73736/67455, 45898/38384 at size 9.0001. Baseline and candidate both miss 694, 1871, and 155 native-support pixels respectively. Smaller aggregate error therefore does not establish parity or justify admission.
