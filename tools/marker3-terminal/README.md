# Marker3 terminal controls

`capture.py OUTPUT` captures size-8 tool-1 Model/Drawing vectors and host-Mesa RTV1 frames using the pinned `marker3-zero` host inputs. `inside` reproduces the skipped terminal segment; `two` and `near` test two source points above and below the 2-unit rejection threshold. The native Drawing and saved-redraw vectors are retained in the compressed caller receipts; the reduced vectors are also checked bit-for-bit by the Rust test. The RT vector bridge and Mesa host limitations match `marker3-size9-expanded` and do not establish device parity.

For the current renderer at 1x, SVG / MuPDF / PDFium aggregate absolute error against native (with the PDF composed on #fcfcfc) is respectively 16580 / 45524 / 17202 for `inside`, 4544 / 36309 / 4042 for `near`, and 9797 / 40249 / 10001 for `two`. The opt-in profile yields 5974 / 37237 / 7177, 1467 / 33905 / 1508, and 3186 / 35243 / 4417. In each case neither output misses native SVG support pixels. These are reader-specific controls, not pixel parity.

`export.rs` exports the controls using the public SVG and direct PDF paths. `compare.py NATIVE_RGBA EXPORT_DIR CASE RECEIPT_JSON` checks the native frame digest and reports the metrics with resvg 0.45.1, PyMuPDF 1.28.2 and pypdfium2 5.14.0 and PDFium 156.0.8076.0. The native captures can be decoded with `zlib.decompress` from the retained `.rgba.zlib` files. Size 9 remains outside the page admission gate.

Reproduce the geometry and SVG/direct PDF comparisons from clean commit `5b0f0c9b1b91e8f13353cbfe939f1b86563f8385` plus `renderer.patch` with `PYTHON=/path/to/python PYTHONPATH=/path/to/pypdfium2 bash tools/marker3-terminal/replay.sh`. It archives only the committed crate, applies the scoped patch, verifies the retained fixture against both native caller receipts, uses the retained lockfiles with offline Cargo, and checks exact reader versions and metrics. It requires the commit and populated Cargo dependency cache. The script uses the shared `/tmp/sdocx-agent-target` and removes temporary output.

Native recapture is host-specific, not a clean-checkout recipe: it requires ignored `scratch/apk-analysis-native/arm64-v8a` Samsung DSOs (Marker3, Model, Renderer, libc++ and Base, PenCommon, Drawing, Graphics, Composer and FountainPen), `scratch/apk-analysis-runtime/python` Unicorn, `scratch/apk-analysis-runtime/binutils-aarch64` objdump and libraries, and `tmp/conformance-cleanup/native-capture-a241793/conformance` Python helper tree. The hash-pinned subset is listed in `tools/marker3-zero/hashes.json`; remaining dependencies, Mesa/EGL and Python packages are not completely pinned. Templates contain the original absolute project root. No clean acquisition recipe for the proprietary inputs or complete runtime closure is provided.

The replay uses a clean archived crate with a scoped source patch, but is not a self-contained checkout: its conformance and tools directories are symlinked to the current workspace to satisfy crate-wide test compilation. It verifies hashes of the Marker3 test fixtures and all six caller receipts used by the geometry test before running; unrelated crate-wide compile inputs reachable through those links are not all pinned. The comparator asserts every listed baseline and profile metric exactly after checking its reader versions.
