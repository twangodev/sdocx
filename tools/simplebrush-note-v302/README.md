# SimpleBrush crossing determinant

In the pinned SimpleBrush ARM64 `CurveStyle::setValue` (library hash and register snapshots in `receipt.json`), RVA 0x1c45c–0x1c464 computes the line determinant from the previous point; the `fmla` at 0x1c534 reuses that same value for the current endpoint. The previous reconstruction independently recomputed the determinant for the second endpoint. On the sixth setValue call in the v301 crossing, native endpoint lane 2 is `423ca256`, versus `423ca257` in the prior reconstruction. This makes the next midpoint edge lane `42380ea6` versus `42380ea7`, and the next drawPath start width `40829840` versus `40829846`. The resulting first three radii of that path differ by 6, 4, and 2 ULP; x/y and all other captured radius lanes match. The same applies to the open-terminal control. These are Unicorn host observations, not a device rendering claim.

Reproduce instruction snapshots with `CROSS_NOTE=1 POINT_COUNT=57 PROBE_SIZE=8 SIMPLEBRUSH_TRACE_OUTPUT=/tmp/simplebrush-v302-instructions.json python3 tools/simplebrush-note-v302/trace.py fraction12 /tmp/simplebrush-v302-native.json --tool 0`. The trace uses the v301 hash-checked capture and records registers before each instruction in the sixth call; the receipt includes opcodes and operand snapshots at the determinant calculation and reuse; it needs the project-local capture inputs documented by v301.

The correction applies to every `set_value_edges` call, across supported tools and profiles. After determinant reuse, the existing full-vector test passes exactly for both crossing variants; the broader SimpleBrush test suite also checks its existing native captures across tools, sizes, and paths. Those captures do not establish universal parity. `cargo test -p sdocx --features pdf,serde --lib simplebrush` passed 86 tests with the shared agent Cargo environment. Fresh crossing and open-terminal native captures also passed the public `two_pixel_native_export_fixture` full-vector assertion and produced paired SVG and direct PDF. SVG alpha L1 versus native for generic/two-pixel was 646971/8388 (cross) and 646702/8287 (open); matched-paper MuPDF RGB L1 was 710111/52312 and 709354/52860. PDFium 156.0.8076.0 RGB L1 was 714209/90766 and 713677/90669. These host comparisons do not establish pixel parity or saved-page/device behavior.
