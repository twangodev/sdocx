# Manager canvas before deferred message

After the v219 preparation, run `python3 tools/pencil2-worker-v277/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v277/probe.py`. This pins v254 and its inherited inputs, initializes the native renderer and host GLES adapters before the synthetic worker, constructs a native RGBA manager canvas, and supplies it through the host `CreatePenCanvas` callback. The deferred message already contains that canvas: the probe asserts pointer identity and does not replace the message field. Native Run calls Update and Draw on the selected drawable and the manager canvas's own subbitmap, with the asserted matrix.

The probe explicitly binds the manager framebuffer before the first readback. It checks the framebuffer and texture attachment against the allocation trace before and after Run; the second readback uses the framebuffer left bound by Run. On this host the Draw control changes 322 bytes, with RGBA SHA-256 `a0230ba18bf716851b4079facb415b265ade62b80ef28bbfcaa0b1853776672e`, equal to the pinned v256 fixture; the skip-Draw control changes zero bytes and has SHA-256 `8123c216413f82bbaa0339c27a43d9822c2a043e20662b27c97874429b996e9a`. The Draw function entry is observed in both controls; the skip hook returns immediately at that entry. The attachment and GL names are host-run observations, and null-data initialization and Mesa are host-dependent.

This removes the later canvas substitution, but the factory callback still injects the manager canvas, the worker queue is synthetic, the message Run and drawable Init are explicit, and the framebuffer is bound by the host for readback. It does not establish automatic scheduling, complete destruction, saved-note traversal, or device behavior. The alpha-only export comparisons connected to this fixture and their limits are described in v274. Transitive runtime dependencies are not fully pinned.
