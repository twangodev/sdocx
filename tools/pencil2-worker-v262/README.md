# Native copy destination ownership

After v219 preparation, run `python3 tools/pencil2-worker-v262/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v262/probe.py`. This extends the pinned v255 capture and v261 copy control with checks along the native destination path. At Graphics `0x90e88`, x23 is the factory-created destination bitmap; its virtual sub-bitmap lookup returns a non-null object at `0x90e9c`, whose virtual texture lookup returns the object used at the copy dispatch `0x90ee8`. That object's words at offsets 40 and 44 are `GL_TEXTURE_2D` and the GL name bound at `glCopyTexSubImage2D` and attached for readback. The Renderer implementation at `0x5f3c8` statically loads those fields for `glBindTexture`. Both modes pass this ownership chain and the v261 readback and allocation assertions.

This identifies the copied-to GL texture with the destination bitmap through the observed native lookups. The bitmap is synthetic and R8; the probe does not establish that a saved page uses this bitmap or copy path, its production queue and destruction lifecycle, or a mapping to Rust/export output. The v255 and v261 host, emulation, error-check and deliberate-stop limitations apply.
