# Montblanc 10–11 point 2× size controls

Fresh synthetic native Drawing captures of zigzag, loop, ascending and hook trajectories exercise sizes 0.5, 1 and 2 with varying pressure. Ascending and hook are independent of earlier 2× trajectories, though they were used in the 1× size controls. The native host-Mesa frames use an explicitly supplied 2× projection. These do not establish saved-page zoom, device output or native PDF export.

The isolated candidate uses the 2× admission gate for 10–11 points at sizes 0.5–2; the baseline uses the previous nine-point limit. Against native frames, SVG/resvg RGB L1 falls from 356,318–500,046 to 44,518–67,227; direct PDF MuPDF falls from 352,618–495,984 to 35,001–55,025, and PDFium from 351,254–497,889 to 34,703–54,182. Candidate coverage exceeds native support in each case. The receipt records all requested inputs, hashes and metrics. Native capture metadata verifies observed size, style, target and projection; the adapter receives the requested points and pressures, but does not record their native readback. Intermediate sizes, arbitrary trajectories and pressures remain unverified.

Unpack `native.tar.gz` into a fresh capture directory and set `MB_CAPTURE_WORK` to that directory; set `MB_EXPORT_WORK` to a separate fresh empty directory. Run `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/long-2x-sizes/compare.py rebuild-verify`. The comparator checks stream and native frame digests, selected source hashes, renderer versions, document and raster hashes, and metrics. Requirements and partial runtime pinning match `../long-paint/README.md`. `capture` takes a fresh empty `MB_EXPORT_WORK` and produces fresh native captures; the archive retains the capture metadata and frames. Never use directories containing unrelated files. Selected source pins are not a complete build closure.
