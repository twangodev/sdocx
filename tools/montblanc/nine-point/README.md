# Nine-point Montblanc diagnostic

The comparison was performed in an isolated experimental snapshot. The bounded unit and 2× opt-ins now admit nine-point strokes at sizes 0.5–2, subject to the existing metadata and record-budget guards. With the sampler point-count guard widened, the test in `candidate.patch` matched all 79 callback types and all six binary32 lanes against `conformance/montblanc-nine-point-native.json`. The host capture runs Drawing on the same synthetic input and asserts the entire callback stream before uploading and painting. Its complete capture is `capture.json.gz`; the separate compressed RGBA8 frame is `frame.rgba.zlib`.

The patch also widens the public opt-in guards for the experiment. A 1x comparison on the native transparent host frame composited over page gray yielded aggregate RGB errors of 15,540/12,599/12,406 for candidate SVG/resvg, PDF/MuPDF, and PDF/PDFium, versus 100,103/99,743/99,107 for generic output. Candidate support was 367–372 pixels versus 316 native pixels. See `comparison.json` for exact counts and generated artifact hashes. These results cover one synthetic input, one scale and one backdrop; they do not establish arbitrary nine-point, saved-note, Android device, or lifecycle parity. Other inputs retain the prior fallback.

For reproduction, use an isolated source snapshot of the current workspace. The retained patches record the historical experiment against the earlier eight-point guard; do not apply them to the current implementation. Run `cargo test -p sdocx --features pdf --lib montblanc` using the project agent Cargo environment. Copy `public-expanded.rs` to `crates/sdocx/examples/montblanc_nine_probe.rs` in the snapshot, then run `cargo run -p sdocx --features pdf --example montblanc_nine_probe -- OUTPUT_1X` and run the same command with `SDOCX_MONTBLANC_DOUBLE=1` and `OUTPUT_2X`. Both output directories must exist. Run `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/nine-point/compare-expanded.py OUTPUT_1X OUTPUT_2X` in the original checkout and compare its JSON output with `expanded-comparison.json`. This requires Pillow, PyMuPDF 1.28.2, pypdfium2 5.9.0 / PDFium 150.0.7869.0, and resvg 0.45.1. The recorded source hashes do not attest the complete comparison build.

The size-0.5 boundary, other paths, native lifecycle, and device output have not been separately captured. To recapture host paint from the original checkout, set `MB_CASE` to the JSON `input` object in `conformance/montblanc-nine-point-native.json`, `SDOCX_CAPTURE_ROOT` to the checkout and `PYTHONPATH` to `scratch/apk-analysis-runtime/python:tools/montblanc/extended-paint/conformance`, then run `capture.py --case baseline --output OUTPUT`. The capture requires the existing local native libraries and host adapters described in `tools/montblanc/extended-paint/README.md`. The capture checks the full stream; the comparator checks the retained frame digest against the capture; host setup and shader behavior do not establish device parity.

Two additional pressure and shape controls at 1× and 2× match complete callback streams and improve all three reader errors against fallback; see `expanded-comparison.json`. `manifest.json` pins the retained inputs, frames, captures, scripts and source snapshots at comparison time; it does not attest the complete build. `expanded-test.patch` records the historical test variation; `public-expanded.rs` drives the expanded comparisons. The 2× host projection is explicitly substituted in `capture-expanded-2x.py`. Other inputs and saved-note or device behavior remain unverified.
