# Nine-point Montblanc diagnostic

The comparison was performed in an isolated experimental snapshot. The bounded unit and 2× opt-ins now admit nine-point strokes at sizes 0.5–2, subject to the existing metadata and record-budget guards. With the sampler point-count guard widened, the historical experimental test matched all 79 callback types and all six binary32 lanes against `conformance/montblanc-nine-point-native.json`. The host capture runs Drawing on the same synthetic input and asserts the entire callback stream before uploading and painting. Its complete capture is `capture.json.gz`; the separate compressed RGBA8 frame is `frame.rgba.zlib`.

The historical experiment also widened public opt-in guards. A 1x comparison on the native transparent host frame composited over page gray yielded aggregate RGB errors of 15,540/12,599/12,406 for candidate SVG/resvg, PDF/MuPDF, and PDF/PDFium, versus 100,103/99,743/99,107 for generic output. Candidate support was 367–372 pixels versus 316 native pixels. See `comparison.json` for exact counts and generated artifact hashes. These results cover one synthetic input, one scale and one backdrop; they do not establish arbitrary nine-point, saved-note, Android device, or lifecycle parity. Other inputs retain the prior fallback.

The experimental patches, public exporters and reader comparators have been retired. The maintained Rust `nine_point_investigative_native_stream` test checks callback types and all binary32 lanes; `nine_point_profiles_admit_bounded_sizes` checks public profile admission. They do not reproduce the historical external-reader measurements.

The size-0.5 boundary, other paths, native lifecycle, and device output have not been separately captured. To recapture host paint from the original checkout, set `MB_CASE` to the JSON `input` object in `conformance/montblanc-nine-point-native.json`, `SDOCX_CAPTURE_ROOT` to the checkout and `PYTHONPATH` to `scratch/apk-analysis-runtime/python:tools/montblanc/extended-paint/conformance`, then run `capture.py --case baseline --output OUTPUT`. The capture requires the existing local native libraries and host adapters described in `tools/montblanc/extended-paint/README.md`. The capture checks the full stream; the native-only verifier checks retained frame digests and bytes against the captures; host setup and shader behavior do not establish device parity.

Two additional pressure and shape controls at 1× and 2× matched complete callback streams and historically improved all three reader errors against fallback; see `expanded-comparison.json`. The 2× host projection is explicitly substituted in `capture-expanded-2x.py`. Other inputs and saved-note or device behavior remain unverified.

The Rust `nine_point_retained_native_capture_integrity` test verifies the five retained native captures and frames, their original compressed-file hashes, native capture scripts and stream fixtures. It performs no export or reader comparison. `manifest.json` retains original comparison-time hashes, including retired sources; the test selects only live native inputs. Historical measurements used resvg 0.45.1, PyMuPDF 1.28.2 and pypdfium2 5.9.0 / PDFium 150.0.7869.0; the manifest does not attest the complete build.
