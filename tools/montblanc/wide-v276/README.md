# Independent size 2.4 control

A fully visible synthetic 12-point curved trajectory with varied pressure was captured using native Drawing on host Mesa. `native.json` retains the input and all 87 callbacks; `capture-1.json` retains the frame and capture pins. In a temporary archive of revision `f7666dd0004173f49c93e7e5115c358dfe52cff2`, the existing `irregular_window_candidate` test passed for all 87 methods and float words when the sampler guard was changed from `> 2.0` to `> 2.4`.

`export.py` constructs isolated baseline and candidate crate copies, changing only the dispatch limit and sampler limit to 2.4 for the candidate. Its 1× reader receipt records native/output support and union RGB L1 error. The candidate reduced SVG/resvg error from 144472 to 21820, PDF/MuPDF from 141892 to 16597, and PDF/PDFium from 139742 to 16165. Native support is 555 pixels; SVG candidate support is 619, versus 178 for fallback. Candidate SVG/PDF sizes are 1,079,768/316,303 bytes versus fallback 1,430/1,911 bytes. The receipt is incomplete for 2×; no 2× capture or candidate comparison was made. Its source hashes pin the tested checkout files, not the full dependency closure. This synthetic host evidence does not establish device, saved-note, or arbitrary-path fidelity. These two trajectories do not justify broad production admission given overcoverage and output growth.

Run `.venv/bin/python tools/montblanc/wide-v276/verify.py` with resvg, PyMuPDF, Pillow and pypdfium2 available. The verifier builds isolated copies in a temporary directory, checks the receipt's source and reader pins, and verifies only the retained 1× document and raster hashes and metrics. It leaves the retained receipt unchanged. The input and stream sidecars are reconstructed and do not independently validate the original stream. The receipt records resvg 0.45.1, PyMuPDF 1.28.2 and PDFium 150.0.7869.0; the full dependency closure is not pinned.

To recapture, run `capture.py --output-dir NEW_DIRECTORY`; the directory must not already exist. To generate a separate export receipt, set `MB_RECEIPT_OUTPUT` to a new file along with `MB_CLEAN_ROOT`, `MB_CAPTURE_WORK`, and a fresh `MB_EXPORT_WORK` before running `export.py build`. Existing receipts are never overwritten.
