# Montblanc 10–11 point size controls

Two distinct synthetic paths at sizes 0.5, 1 and 2 were freshly captured through native Drawing and host Mesa at unit scale. In an isolated crate, the existing long-stream Rust test was extended with `streams.json`; all methods and six binary32 lanes matched for all six captures. The candidate admits 10–11 point unit-scale inputs at sizes 0.5–2; the separate 2× profile remains limited to size 1.5 for these lengths. Against native composited frames, RGB L1 fell in all 18 comparisons: SVG 97,972–111,925 to 14,771–16,894, MuPDF 96,616–111,224 to 11,334–13,060, and PDFium 95,510–111,347 to 11,244–12,855. See `receipt.json` for inputs, hashes, output sizes, and support. These are host synthetic controls, not native PDF or device parity.

For replay, unpack `native.tar.gz` to a fresh capture directory and set `MB_CAPTURE_WORK` to it; set `MB_EXPORT_WORK` to another fresh empty directory. Run `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/long-sizes/compare.py rebuild-verify`. The comparator checks the full native streams against `streams.json`, native frame digests, pinned selected source hashes, reader versions, artifacts and metrics; it refuses a nonempty export directory and does not overwrite the receipt. Requirements and partial native runtime pinning match `../long-paint/README.md`. `capture` uses a fresh empty `MB_EXPORT_WORK` and does not overwrite existing captures. The receipt pins selected files, not the full build closure. The comparison reconstructs the prior nine-point baseline from the final candidate gate; it fails if selected pinned sources change.

The durable `long_independent_native_stream` Rust test includes all six streams. It compares every method and float lane. Capture metadata independently checks observed size, style, target and matrix; the capture does not record a native readback of the requested point and pressure arrays. The requested arrays are supplied to the adapter and tied to their complete callback streams in the fixture. The receipt also pins the comparison script, public harness and generated dispatch and harness sources. The source pins describe the final rebuilt candidate and selected inputs, not the complete build closure.
