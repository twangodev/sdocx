# Narrow nine-point Montblanc host controls

Two synthetic nine-point trajectories at sizes 0.2 and 0.4 were captured through native Drawing and host Mesa at 1× and 2×. Within each path and scale, the complete native callback streams and frame hashes agree at both sizes. The Rust sampler matches all six binary32 lanes and callback types for the four 1× streams in `streams.json`. The explicit unit and 2× profiles now admit nine-point strokes at the existing overall 0.1–2 size guard; size 0.1 and intermediate sizes extrapolate from these controls and the previously captured finite size clamp. Eight-point admission remains unchanged.

`receipt.json` compares public SVG with resvg and direct PDF with MuPDF and PDFium against those same native frames. Across all eight cases, the candidate lowers RGB absolute error for all three readers. It overcovers native support, and the admitted path produces much larger exports than the fallback. This is synthetic host evidence, not saved-note, device, general lifecycle, or arbitrary-input parity.

The compact archive retains the native capture JSON and callback streams. To reproduce, extract it into a fresh temporary directory, set `MB_CAPTURE_WORK` to that directory and `MB_EXPORT_WORK` to another fresh temporary directory, then run `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/nine-narrow/compare.py rebuild-verify`. It builds isolated baseline and candidate copies using the shared agent Cargo target, then checks the complete receipt. This requires resvg, Pillow, PyMuPDF and pypdfium2 in the versions recorded in the receipt, as well as the current source and dependencies. The receipt pins selected sources, not the entire build closure. To recapture, run `compare.py capture` with those Python dependencies and the local native runtime described in `tools/montblanc/many-point-paint/README.md`; native libraries and transitive host adapters are not fully pinned. The script uses Python assertions and must be run without optimization.
