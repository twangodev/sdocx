# Longer Montblanc host controls

Two fresh synthetic Drawing/host-Mesa captures at 2× and size 1.5 cover a 21-point zigzag and 24-point arc. The adapter supplies points and pressures without independent native readback. A scratch candidate extends the three 20-point guards to 24; the fallback retains the current limits. For the 21-point case candidate versus fallback RGB absolute error is 47,015 versus 511,816 in resvg, 38,234 versus 512,831 in MuPDF, and 37,621 versus 536,738 in PDFium. The 24-point candidate and fallback outputs are byte-identical; the reason the candidate fell back was not isolated. These 2× results do not establish saved-note, device, native PDF, or arbitrary-path parity.

Capture with `MB_EXPORT_WORK` set to a fresh empty directory and `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/longer-probe/compare.py capture`. For comparison unpack `native.tar.gz` into a fresh directory, set `MB_CAPTURE_WORK` to it and `MB_EXPORT_WORK` to another fresh empty directory, then run the same command with `rebuild-record`. It copies the crate into that temporary directory and changes only the copies. Native runtime dependencies and partial pinning follow `../long-2x-sizes/README.md`. The receipt records frame hashes and renderer metrics; selected source hashes do not describe the complete build closure. Reproducible document intermediates are not retained.

The 24-point arc falls back at the public input check: coordinates such as 3.71 are not exactly representable as f32, which `prepare` requires. This precedes the geometry and patch-budget checks. Two further fresh controls use integer coordinates: a 21-point hook and a 24-point zigzag. Their candidate versus fallback RGB absolute error is respectively 63,055 versus 446,173 and 80,507 versus 576,982 in resvg; 53,854 versus 443,252 and 70,272 versus 568,923 in MuPDF; and 53,071 versus 431,346 and 68,735 versus 558,180 in PDFium. `holdout.py` and `holdout-native.tar.gz` use the same commands above with a separate fresh capture directory; the corresponding metrics are in `holdout-receipt.json`.

An isolated crate with the point-count guards widened to 24 passed the existing `long_independent_native_stream` test after appending all four cases from `streams.json`: every callback and float lane matched the native streams bit for bit. This test checks the sampler, including the decimal-coordinate arc, independent of public input admission. The 2× candidate remains experimental.

At 1×, fresh captures of the same hook and zigzag also favor the candidate: RGB absolute errors are 27,221 versus 174,876 and 32,031 versus 207,115 in resvg, 19,627 versus 175,250 and 24,975 versus 204,132 in MuPDF, and 19,279 versus 146,397 and 24,107 versus 182,494 in PDFium. `holdout-1x.py`, its native archive and receipt retain these controls. The public unit-scale profile now accepts 21–24 points at size 1.5; the 2× gate remains capped at 20. Intermediate point counts and other trajectories are extrapolations; the same input and output limits continue to apply.

Run `rebuild-verify` with the same fresh-directory setup to verify every retained case, native frame and stream hash, document and raster hash, byte length, metric, and selected source pin. The three receipts were rebuilt from the committed source scope, excluding unrelated checkout changes. The generated harness uses the copied fixture at its relative repository path, so build-source hashes do not depend on the temporary checkout location. Source pins remain partial, not a complete build-closure guarantee.
