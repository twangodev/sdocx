# Montblanc redraw-window controls

Synthetic native Drawing on host Mesa replays a contiguous subset of earlier callbacks after `AddEndPoint`. With alternating points spaced seven units apart, lengths 9, 11, 12, and 13 produce first-pass/replay counts 45/36, 54/27, 58/18, and 63/27. For lengths 11, 12, and 13, every replay callback is `AddPoint` and all six float words match first-pass records beginning at offsets 18, 27, and 27 respectively. At length 9, replay begins at position zero, but the initial `AddStartPoint` differs from its replay `AddPoint` in call and opacity. An independent ten-point trajectory with distinct pressure values replays all six words and callback methods from first-pass offset 18 for 18 callbacks. Inserting one or three spatially identical samples with identical pressure into the nine-point trajectory produces ten- and twelve-point inputs with callback streams identical in every method and float word to the original nine-point stream. Timestamps were regenerated as 100 + 10 times the new sample index, so later timestamps differ; tilt and orientation remained zero. This shows the replay behavior is not determined by raw input count alone. These controls support a moving window but do not identify the native rule or justify general admission.

`streams.json` retains inputs, complete callback streams, frame hashes, and native input and host GL pins. Captures used `tools/montblanc/narrow-probe/capture.py`, `--case baseline`, the input in each receipt case as `MB_CASE`, `SDOCX_CAPTURE_ROOT` set to the repository root, and `PYTHONPATH` set to `scratch/apk-analysis-runtime/python:tools/montblanc/extended-paint/conformance`. Complete runtime dependencies are not pinned. These controls do not establish saved-note or device behavior, or compare public SVG or PDF exports.

Run `python3 tools/montblanc/redraw-window/verify.py` to check the retained streams against fixed expected counts, offsets, exact callback symbols, and duplicate-input construction. It verifies the capture script hash and checks digest syntax; it does not re-hash the native libraries or reconstruct the retained frame from the frame hash.

`event-traces.json` records a later passive native trace of the natural `endPen` call and `drawLine` entries with the endPen caller return address, including the terminal MotionEvent bytes, entry state, callback words, and per-call receiver state. In these nine controls `endPen` invokes `drawLine` five times, with the last five nonterminal positions of the unduplicated trajectory. The two new controls insert a same-position point with pressure 0.9 or a one-unit move with pressure 0.9 into the nine-point input: both preserve the complete original callback stream and all six captured drawLine register words. The alternating state bytes and a five-event window are observations, not a proven general state-machine rule. Addresses are from this host emulator mapping and are not portable addresses.

Reproduce with `trace.py` using the capture environment above and each receipt input as `MB_CASE`; redirect stderr to `/tmp/mb-window-CASE.log` and use a new output path per capture. `extract_trace.py /tmp` collects those logs and the two new `mb-window-CASE-input.json` files into the receipt. `verify.py` checks the retained trace and source hashes, complete frozen streams, and the changed-pressure and short-movement controls. No sampler admission or export comparison follows from these observations.

`irregular-native.json` adds an independent 16-input trajectory with varying pressure and two diagonal moves of length sqrt(2). In a separate snapshot of the crate, `irregular-candidate.patch` extends only the test sampler and skips `saturating_sub(accepted_nonterminal_count, 7) / 2` replay segments. The test compared the complete native stream: 83 callback methods and all six float words matched. Apply the patch only to an isolated copy of the crate, set `MONTBLANC_WINDOW_NATIVE` to the absolute receipt path, and run `cargo test --offline -p sdocx --features render --lib irregular_window_candidate -- --nocapture` using the shared Cargo settings in AGENTS.md. This candidate is an inference from a small set of trajectories; it does not prove the internal window rule, test exports, or widen public admission. The receipt retains native input and host GL pins, but its verifier cannot independently establish the recorded Rust test result.

`irregular-variants.json` retains a 14-input prefix, a 17-input extension, and that 17-input extension in reverse, including each native stream and entry state. The same isolated test candidate matched every method and float word in all three streams (73, 97, and 95 callbacks). They vary the first trajectory rather than constituting independent trajectory families. To rerun, provide each variant case as a standalone JSON object to `MONTBLANC_WINDOW_NATIVE`; the verifier checks retained structure and inputs, not the historical test execution.

`export-receipt.json` compares the four irregular inputs at 1× and 2× against fresh native captures, using resvg for SVG and MuPDF and PDFium for direct PDF. Every capture's callback stream exactly matches its retained input stream. In all 24 candidate/reader combinations RGB absolute error is lower than fallback; candidate support includes all native support and overcovers it. The 2× 256-pixel viewport clips parts of these long trajectories, so those comparisons establish only the visible region. The SVG and PDF documents are much larger with the candidate. This remains synthetic host evidence, and the candidate remains isolated.

With resvg, Pillow, PyMuPDF and pypdfium2 available, run `export-compare.py capture` with a fresh `MB_CAPTURE_WORK` and `MB_EXPORT_WORK` to regenerate native captures; then run `export-compare.py rebuild-verify` with `MB_CAPTURE_WORK` pointing to them and a fresh `MB_EXPORT_WORK`. The script builds isolated candidate and fallback drivers and compares both PDF readers. `verify.py` checks receipt structure and recorded inequalities only; `export-compare.py verify` rerenders existing generated exports and verifies the full receipt. The source pins and runtime boundary follow the nine-point comparison and are not a complete build closure.

The export receipt pins the diagnostic test patch, original public driver and manifest, and the generated isolated driver, sampler and dispatch source for both modes. The export sampler is generated by checked single-occurrence substitutions; the separately pinned test patch supplies the stream diagnostic and is not applied by the exporter. The four related trajectories use one pen size, and the test-only upper bound of 32 points is a diagnostic convenience with no validation beyond these controls. Source hashes do not capture the full transitive dependency closure.

`independent-native.json` adds four independently constructed paths at lengths 10, 12, 20 and 32 and pen sizes 2.4, 0.6, 3.0 and 1.2, respectively. Their first-pass/replay callback counts are 32/14, 44/14, 49/28 and 118/15; the complete replay sequences match first-pass offsets 9, 21, 14 and 95 respectively, including symbols and all six float words. These are native observations, not candidate or export comparisons. Run `independent-capture.py --output /tmp/new-independent-receipt.json` using a path that does not exist; it captures in a fresh temporary directory and removes frame intermediates. `independent-verify.py` checks frozen input and callback hashes, native and GL pin values, callback sequence and unique replay offsets. It checks recorded frame digests against fixed values but does not re-hash native libraries or reconstruct frame pixels. These observations alone do not justify widening admission.

The isolated `irregular-candidate.patch` test was run against all four independent cases. The 0.6-size vertical12 and 1.2-size loop32 cases match every method and all six words across 59 and 134 callbacks, respectively. The 2.4-size zigzag10 and 3.0-size turn20 cases return `UnsupportedWidthBranch` before generating a stream, because the existing sampler rejects sizes above 2.0. This is not a stream mismatch or evidence supporting the larger-size branch. The test can be rerun by extracting each case from `independent-native.json` as a standalone JSON object and following the isolated test instructions above; link the project `tools` directory into the snapshot for compile-time test fixtures.

`independent-export-receipt.json` compares fresh native frames for the two matching inputs at 1× and 2× with the isolated candidate and existing fallback, using resvg, MuPDF and PDFium. All four recaptured callback streams equal the retained independent streams. Across all 12 comparisons the candidate has lower RGB absolute error than fallback, covers native support completely, and overcovers it; this is synthetic host evidence, not device or saved-note parity. The 2× viewport may clip the trajectories. The 32-point diagnostic limit remains a test bound, not a demonstrated safe upper limit; no public admission is changed.

`independent-export-native.tar.gz` retains the four capture JSONs and streams. Extract it to a fresh `MB_CAPTURE_WORK`; use a separate fresh `MB_EXPORT_WORK` and run `PYTHONPATH=/tmp/marker2-pdfium-python .venv/bin/python tools/montblanc/redraw-window/independent-export-compare.py rebuild-verify` with the shared Cargo settings and the renderer dependencies described above. `verify` rerenders existing generated exports. For fresh native frames, run `capture` with a fresh `MB_EXPORT_WORK`; capture writes there, so set `MB_CAPTURE_WORK` to that same directory for the later comparison. Source and library pins do not cover the full dependency closure.

The independent exporter refuses to build when any of its six build or export directories already exists, and capture refuses to overwrite its capture script or output files. If `MB_EXPORT_WORK` is omitted, it creates and prints a unique temporary directory. Negative controls with existing build and capture sentinel files confirmed refusal and preserved both sentinels. The script does not delete existing work directories.

The capture writes an input sidecar immediately before each native invocation; comparison checks it against the selected independent input and checks the recorded pen size, color, transform, target dimensions, RGBA byte count, and SVG raster dimensions. The sidecar records the submitted input; exact native callback stream equality provides separate runtime evidence.
