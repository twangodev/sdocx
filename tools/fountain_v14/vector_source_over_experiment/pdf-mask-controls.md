# Candidate PDF mask controls

`pdf_mask_controls.py` tests two specific explanations for the candidate's PDF differences using the pinned canonical and scale-aware source-3 PDFs and the native white 1× instance-prefix frames. For the canonical PDF it changes the linear luminosity-mask form group from DeviceRGB to DeviceGray; that PDF has no radial mask group, so the radial-only variant changes no objects and the combined variant repeats the linear change. For the scaled PDF it changes the linear and radial mask groups separately and together. It also separately changes the PDF shading `AntiAlias` flags from false to true. It leaves the colored isolated group unchanged. The exact PDF hashes and object assertions bind these interventions to these exports; both PDFs contain vector output and no embedded images.

In the [receipt](pdf-mask-controls-receipt.json), every rendered crop hash is unchanged from baseline for all four prefixes (1, 5, 25, 101), for both MuPDF and PDFium. The canonical baseline errors are 503, 949, 3,139, 9,751 in MuPDF and 503, 992, 3,150, 10,106 in PDFium. The scaled baseline errors are 835, 1,912, 4,302, 13,874 and 1,090, 2,222, 3,997, 14,157 respectively. These interventions therefore do not explain these reader errors or provide a correction in this control. They do not rule out other transparency-group, mask sampling, coverage, or compositing differences, and do not establish native PDF or device parity.

Reproduce candidate exports by the isolated-copy procedure in README.md, then run `/tmp/sdocx-v190-readers/bin/python tools/fountain_v14/vector_source_over_experiment/pdf_mask_controls.py EXPORT_DIR OUTPUT.json` with PyMuPDF 1.28.2, pypdfium2 5.9.0, and Pillow 12.1.1 installed (PDFium version is recorded in the receipt). The absolute interpreter path identifies the local environment used for this receipt; any equivalent environment with those packages may be used. The source and export hashes are checked, but the full build dependencies and executable are not attested.
