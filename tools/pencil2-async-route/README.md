# Asynchronous drawing matrix route

`python3 tools/pencil2-async-route/check.py` checks the checkout-local Drawing DSO hash, selected instructions and one vtable relocation. Manual disassembly gives the following conditional static route:

* `ObjectAsyncDrawing::DrawingData` receives an optional Matrix3 from its caller. When present, its constructor copies it to offset 68 and marks offset 104 present.
* `ObjectAsyncDrawing::DrawObjectList` copies this optional into a temporary, then passes it to the `AsyncDrawingData` constructor, which copies it to offset 60 and marks offset 96 present. That constructor also creates a new object list; a type-1 object follows the `ObjectStroke::CloneDrawData` branch before insertion.
* `ObjectAsyncDrawingImpl::draw` selects either null or the matrix at offset 60 according to the presence byte at offset 96, and passes that pointer in argument x4 to a virtual call at byte offset 16 from its drawing object's vtable address point. The default `ObjectDrawing` vtable's corresponding entry relocates to `ObjectDrawing::DrawObjectList`, the entry previously exercised in the synthetic synchronous list probe. The method supplies a newly created bitmap for that call.

This identifies a concrete asynchronous caller that can pass a caller-supplied Matrix3 to the existing native list path. It does not establish what a real page supplies, that the queued request ran, that the virtual object uses the default vtable, or a conversion to Matrix4 or RTV4 paint. Static branches, virtual methods, symbol interposition and cancellation can change the actual route. The check samples instructions and relocation rather than proving all control flow or copies; the DSO is pinned by hash but its APK provenance, host binutils and transitive tool dependencies are not independently established. No target execution is claimed.

`python3 tools/pencil2-async-route/constructor-probe.py` exercises the native `DrawingData` constructor under the pinned synthetic list adapter. It checks absent and present optional matrices with both a null and a non-null synthetic bitmap, and verifies the retained receipt. Use `--write-receipt` to regenerate it. The presence byte is 0 or 1 as supplied, and the present matrix is copied byte-for-byte. A host callback substitutes `SPGraphicsFactory::RefBitmap` and records four calls per constructor; the non-null case passes the synthetic bitmap in the first call. The [receipt](constructor-receipt.json) records hashes and observations. This adapter intervention does not implement bitmap reference ownership. The subsequent list call is the existing separately invoked synchronous probe, not an asynchronous submission; no actual page inputs, asynchronous execution, Matrix4 or paint are established.

`python3 tools/pencil2-async-route/clone-probe.py` invokes the native `AsyncDrawingData` constructor with the synthetic one-object list and present matrix. In this adapter the constructor produces a list with count one and copies the matrix and presence flag; its four bitmap reference calls are intercepted by a host callback. The following synchronous list probe still uses the original list. In an exploratory run using the copied list instead, native dispatch reached `drawObjectStroke` but not the expected Pencil2 `RedrawPen` event; the reason remains unknown. The count is a shallow observation: it does not establish object identity or independence. No destructor path is exercised. Neither run establishes queued execution, bitmap ownership, or cloned-stroke paint. The [receipt](clone-receipt.json) pins the probe and selected inputs; use `--write-receipt` to regenerate it.

`python3 tools/pencil2-async-route/clone-context-probe.py` compares that same synthetic source before and after native `ObjectStroke::OnAttach` to an explicitly constructed `ModelContext` and `StringIDManager` containing Pencil2 and `14;`. In both cases the list delivers a distinct stroke pointer to `drawObjectStroke`. Without attachment, `CopyDrawingData` observes a null context pointer at Model RVA `0x2eb168`, the cloned stroke's `GetPointCount` returns zero inside `drawObjectStroke`, and the latter exits at its count check before pen selection. With attachment, the context pointer is nonnull, the cloned stroke's count is four, and the list dispatch reaches V14 `RedrawPen` and 84 `AddPoint` calls. Both runs use the same constructor bitmap callbacks and synthetic synchronous list adapter; the attached run supplies the model context as an explicit intervention. This establishes the cause for this adapter's earlier empty clone, but does not establish actual queued execution, full clone independence or ownership, bitmap lifecycle, automatic paint, saved-page scheduling, or device behavior.

`python3 tools/pencil2-async-route/draw-attempt.py` explicitly invokes native `ObjectAsyncDrawingImpl::draw` with a fabricated request containing the attached synthetic clone. Native dispatch reaches the distinct cloned stroke, whose point count is four, then V14 `RedrawPen` and 84 `AddPoint` calls. Both observed Matrix3 setter calls receive the supplied matrix. The native function returns, but its residual return register is not interpreted as a status. [Receipt](draw-attempt-receipt.json) pins the probe and selected binaries. RefBitmap, CreateBitmap, and ReleaseBitmap are host callbacks; synthetic virtual bitmap and graphics methods supply the handoff, and the queue remains deferred. This does not establish ordinary queue scheduling, bitmap ownership or lifecycle, Matrix4 handoff, actual paint, saved-page behavior, or device output.

`python3 tools/pencil2-async-route/submit-probe.py` invokes native `ObjectAsyncDrawing::DrawObjectList` with a constructed synthetic DrawingData and attached four-point stroke. Its bitmap adapter passes the native submission checks; the host marks initialization complete and supplies an empty completion list. The native submission returns 1 and calls an intercepted `RequestDraw` once with a native-created request containing one item and the supplied Matrix3. The host then explicitly invokes native `ObjectAsyncDrawingImpl::draw` on that same request. It reaches a distinct four-point clone, V14 `RedrawPen`, 84 `AddPoint` calls and two canvas setters with the supplied matrix; the native draw returns. The [receipt](submit-receipt.json) records this bounded observation and selected hashes. The `RequestDraw` callback substitutes for scheduling, and synthetic bitmap, graphics and context callbacks remain in use. An extra preliminary clone construction also occurs in the adapter. No actual asynchronous queue execution, bitmap ownership, Matrix4 handoff, GPU paint, saved-page behavior or device output is established.

`python3 tools/pencil2-async-route/enqueue-probe.py` extends the same synthetic submission through native `RequestDraw`, `findRequest`, and `addRequest`. With an initially empty synthetic list, native code inserts one request and calls the host condition-signal adapter once. The host then explicitly invokes native `draw` on the queued request, reaching the four-point clone, 84 `AddPoint` calls and two supplied Matrix3 setters. The [receipt](enqueue-receipt.json) records the observation. Lock and condition operations are host callbacks, and the worker does not run; bitmap, graphics, model context and allocation adapters remain synthetic. This does not establish thread scheduling, concurrent safety, ownership, Matrix4 handoff, paint, or saved-page or device behavior.
