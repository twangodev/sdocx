# Isolated Pencil2 PDF object transaction

Run `tools/pencil2-pdf-transaction-v202/run.sh` with cached Rust dependencies. The standalone crate uses its committed lockfile with `--offline --locked` and the shared agent target directory. This is a focused `lopdf` experiment, not an integration into the renderer. It receives already-created 192×192 RGBA frames, checks frame shape and conservative frame, stream-byte, object-count and object-ID bounds before creating streams or PDF resources, and builds the new form and alpha-state objects in a separate document. Its IDs start above the destination's maximum. It appends the staged objects only after all forms succeed. The destination document is not cloned.

Three tests exercise two fields and a dense full-frame stream. They check exact preflight limits, one-below limits, malformed frames, ID overflow, and injected failures during command encoding, alpha-resource creation, and after each staged field against a pre-existing marker stream and trailer. Successful insertion checks form order, prior marker and trailer preservation, two pixel commands, and every one of the 255 alpha-resource references per form. Each emitted command is checked against the 256-byte bound, and the dense-frame test checks the complete stream against its preflight bound. These are real `lopdf::Document` objects but not the renderer's scene registry or a complete renderable page. The byte bound covers form commands only; resource and allocation overhead are bounded by object count, not measured in bytes. The supplied frame buffers and sampler work are outside admission. The transaction does not cover scene marker registration, SVG, serialization, reader output, device fidelity, or process failure/OOM during the final map append. This is not evidence for production admission.
