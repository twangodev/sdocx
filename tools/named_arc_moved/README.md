# Native saved moved Arc controls

The probe creates a native shape, sets type 20, bounds (10,20,210,120) and red fill, calls ObjectShape::MoveControlPoint (0x3970d8) for each control, writes a native frame, reloads it, and records native Drawing's SkPath calls. It asserts source and loaded bounds, outline and fill paths match. Source and loaded control getters can differ by a few ULPs, retained separately in each receipt. Five runs use allocation fills 0, 85, 165, 255, 0. The retained frames are native writer outputs, not edited frames.

Both-20/100/150 move the start to (20/100/150,20) and end to (40,100). Seam-0/1 use (210,69) and (210,71) in opposite orders. Edge-0 uses (1000,-400) and (-400,300), edge-1 (111,69) and (109,71), edge-2/3 use (210,69.999) and (210,70.001) in opposite orders, and edge-4/5 use (10,70) and (110,120) in opposite orders. The reconstruction's exact saved-outline gate admits both controls, the seam cases, edge-0 and edge-5; edge-1 through edge-4 fall back. This is bounded matching behavior, not a general moved-control fidelity guarantee.

Run `python3 tools/named_arc_moved/replay.py /absolute/path/to/arm64-v8a /absolute/path/to/unicorn/lib`. Replay checks the complete rustc-reported source set and SHA-256 hashes in `sources.json`, including the substituted capture and host thunks, as well as the Unicorn library. The compiler is not pinned. The capture checks native library and host math hashes, uses bounded substitutes for allocations, host math, Canvas transformations and recording, and traps unbound imports; the audit verifies reached PLT bindings. Native Drawing records a sector fill then open outline. It does not execute device Canvas, raster pixels, full document load or native PDF export. Rust SVG/PDF structural checks do not establish pixel parity. The exact-match gate and portable libm avoid making platform atan2 equivalence a prerequisite for fallback; Android math parity remains unverified.
