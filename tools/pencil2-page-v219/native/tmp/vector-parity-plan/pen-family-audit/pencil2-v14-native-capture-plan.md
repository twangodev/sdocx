# Pencil2 v14 saved-stroke native capture plan

Status: source-only plan. No emulation, GL, build, or fixture execution was performed. The existing Pencil3 Model → Drawing fixture runner is reusable as a harness skeleton, but its Pencil3/RTV1 stream hook and shader fake-renderer do not prove Pencil2 output. Add a Pencil2-specific runner beside it and keep the explicit synthetic context boundaries in its receipt.

## Pinned route and defaults

- DSO: `scratch/apk-analysis-native/arm64-v8a/libSPenPencil2.so`, 773592 bytes, SHA256 `3e7d7118ea0fea370d491a5582ac81c09dc063ac75dbcc396abdc32976a42b0f`.
- Default comes from `SPen::Pencil2::Pencil2()` VA `0x59880`: the constructor passes `14;` through `Pen::SetAdvancedSetting`, sets size `0.228f`, and color `0xff000000`.
- Use the real `ObjectDrawing::drawObjectStroke` route, set only the ObjectStroke pen name to `com.samsung.android.sdk.pen.pen.preload.Pencil2`, and leave `ObjectStroke::SetAdvancedPenSetting` uncalled. Do not call `SetAdvancedSetting` on the created pen or force a setting through `Pencil2::GetStrokeDrawableGL`.
- Verify the factory created a `Pencil2` and that `GetStrokeDrawableGL()` returns the v14 drawable class through its vtable/RTTI. The constructor default should produce GLV14 → RTV4; abort the capture if that is not observed.
- Runner skeleton: `tmp/vector-parity-plan/chinesebrush-paint-scale-work/conformance/pencil3_selector_probe_native.py`. Reuse its Model/Drawing loader, native `ObjectStroke` setters/getters, factory-return snapshot, Drawing route, explicit context setup, saved `RedrawPen` replay, and per-library hash receipts. Replace Pencil3 library/name/symbol pins and v1 RT hook with Pencil2 and v14/RTV4 symbols. Preserve its `null` advanced-setting meaning: do not synthesize an empty setting string.

## Bounded input cases

Use ordinary `tool_type=2`, `stroke_type=0`, solid opaque black (`0xff000000`), no fixed width, and rainbow disabled. The Pencil2 constructor size (`0.228f`) is captured before Drawing applies ObjectStroke data; choose and record the ObjectStroke size separately as an explicit controlled input, or capture its native default getter unchanged. Keep the existing fixture's explicit `1920x1080` context only if retained as a labelled synthetic controlled profile; it is not evidence of device screen dimensions. If the capture needs a real device profile, obtain that profile from the target app/context before running instead of guessing.

1. Width/alpha core: a single-point stroke with pressure 0.5, tilt 0, orientation 0, timestamp 100, and native ObjectStroke size-level default (read and record it; do not set an assumed value). This bounds ordinary-tool default geometry and color without pressure/time/tilt variation.
2. One timed four-point line: points `[(0,0),(10,0),(20,0),(30,10)]`, timestamps `[100,116,132,148]`, pressures `[0.25,0.5,0.75,1.0]`, tilts `[0,0.25,0.5,0.75]`, orientations `[0,0.25,0.5,0.75]`, native ObjectStroke size-level default (read it; do not override). Compare only the same native values across live Drawing admission and saved ObjectStroke replay. Treat these channels as caller inputs; this is not a claim that the values match Samsung's serialized units.

Populate input using native Model `ObjectStroke::SetPoint(PointF const*, float const*, int const*, float const*, float const*, int)` and setters for pen name, tool type, stroke type, size, color, and (only if deliberately testing) size-level. Snapshot `GetPoint`, `GetPressure`, `GetTimeStamp`, `GetTilt`, `GetOrientation`, `GetSizeLevel`, `GetPenSize`, `GetColor`, and advanced setting bytes before Drawing. Preserve float bit patterns and timestamp integers in the receipt.

## Native route, lifecycle, and complete buffer capture

Trace and require this path per case:

1. `ObjectDrawing::drawObjectStroke(...)` invokes `createPenInst` for Pencil2. Snapshot constructor-return bytes before Drawing applies ObjectStroke values; separately record effective getters afterward. Confirm no advanced-setting setter/override was injected and `14;` remains the native Pencil2 constructor state.
2. Selected primary drawable is `Pencil2StrokeDrawableGLV14`; saved replay target is `Pencil2StrokeDrawableGLV14::RedrawPen(ObjectStroke const*, RectF*)` at VA `0x73bb8` (non-virtual thunk VA `0x73bd0`). The implementation `redraw(ObjectStroke const*, RectF*, bool)` is VA `0x73028`.
3. Snapshot RT pointer from drawable `+16`, require its vtable to identify `Pencil2StrokeDrawableRTV4`, and trace every `Pencil2StrokeDrawableRTV4::AddPoint(Vector2<float>*,float,float,float,int,Vector3<float>)` call at VA `0x98a98`. ABI at entry: `x0=this`, `x1=Vector2*`, `s0..s3` four float args, `w2` integer arg, `s4..s6` Vector3. Record raw register bits and coordinate/color pointed bytes.
4. Before/after each AddPoint, read the `std::vector<float>` descriptor referenced by `*(RT+80)` (three native pointers begin/end/capacity); bounds-check `begin <= end <= capacity`; capture the full after-buffer and delta, not only call arguments. `RTV4::Update(bool)` at `0x995f4` derives record count from float-buffer length divided by 14, so assert each AddPoint grows the same buffer by 14 floats (56 bytes) and final stream length is a multiple of 56. Save the vector both after each insertion and at saved redraw return.
5. `Pencil2StrokeDrawableGLV14::drawPoint` calls RTV4 AddPoint from VA `0x74750`. Saved redraw gathers all source arrays via ObjectStroke getters and synthesizes MotionEvent samples; assert the four getter-backed inputs and per-point callback sequence match the chosen fixture exactly. Compare live Drawing's buffer and direct saved replay byte-for-byte only when the route actually invokes both; do not substitute an independently constructed RT object.
6. Capture Clear/Update/order: hook `Pencil2StrokeDrawableRTV4::Clear()` VA `0x995d8`, `Update(bool)` VA `0x995f4`, and `Draw(ISPSubBitmap*,Matrix4<float>&)` VA `0x99660`. Record their receiver addresses and ordering; use a fresh factory/drawable for each case. No RNG import is currently visible in Pencil2's dynamic undefined symbols; preserve the fixed pattern data hash and record any runtime RNG/time calls if traces reveal one.

## Shader, textures, sampler, and eventual pixel capture

- Require the selected RTv4 `Init()` at `0x984ac` to create `Pencil2StrokeShaderV3`; symbols `szVertexShader`/`szFragmentShader` are at VAs `0x3e872`/`0x3ebc4`. Pin exact extracted source bytes/hashes in the eventual receipt.
- RTv4 `buildTextures(int,int)` at `0x981ac` creates a 150×150 grain bitmap from `g_backgroundPtn` and a separate 100×300 point bitmap from `g_pointPtn`. `setTextures` at `0x98350` converts each byte to a 32-bit texel; it uploads 22,500 grain texels and reshapes the point data into a 3×100×100 atlas. Preserve source-array dimensions, hashes, upload dimensions, format/type, and the texture object IDs.
- On actual `RTV4::Draw`, capture `ShaderManager` selected program, resolved uniforms, active texture unit, each `glBindTexture` target/id, and `glUniform1i` values for shader samplers `sampler0` and `sampler1`. The fragment source samples grain from `sampler0.r` in screen coordinates and the three-tile point mask from `sampler1.r`; do not infer unit bindings solely from declaration order.
- Record actual blend descriptor/raw tuples created in `Init`: color `(fn=0,src=6,dst=7)`, alpha `(fn=0,src=1,dst=7)`, with descriptor enabled. Resolve enum semantics from Renderer headers/runtime calls before comparing output.
- Pixel capture can reuse the reviewed full-route Mesa/queue pattern in `tmp/vector-parity-plan/fountain-as18-v16-mesa-candidate-v6/capture_as18_v16_mesa_pair.py` and the RT draw/readback patterns in `tmp/conformance-cleanup/native-capture-a241793/conformance/inkpen2_paint_native.py`; neither supplies Pencil2 evidence. Wire the adapter to Pencil2's `ISPBitmap`/`ISPSubBitmap`, shader manager, render target, and task queue. Call the native `RTV4::Draw` on the buffer produced above, read back the full RGBA target before/after on a fixed background, record target dimensions/origin/scale and GL vendor/renderer/version, and pin readback bytes. Existing Pencil3 `draw_probe.py` uses a fake renderer interface and is useful for hook patterns only; it is not Pencil2 GL pixel evidence. No Pencil2 renderer pixels are asserted by this plan.

## Reuse limits

The Pencil3 saved caller runner is a Unicorn Model/Drawing path with host stubs for graphics/context/task-queue boundaries. It can produce Pencil2's native Geometry/AddPoint stream after its library/selector/RT hooks are adapted. The Pencil3 paint probe can guide shader/uniform capture, but its texture units, RT structure, shader, blend state, and version must not be reused as Pencil2 facts. A true native-active-sampler and GPU readback receipt remains contingent on the GL/Mesa adapter accepting Pencil2's texture resources and RTV4 draw path.
