# Manager message framebuffer trace

Run `python3 tools/pencil2-worker-v273/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v273/probe.py` after the v219 preparation. This extends v272 with markers around the native message Run in the host GLES callback log. In the draw run, the logged bind and texture-attachment calls inside Run consist of `glBindFramebuffer(GL_FRAMEBUFFER, 2)`; texture 5 was already attached to framebuffer 2, and the endpoint attachment queries remain unchanged. With Draw skipped there is no such call. This checks only `glBindFramebuffer` and `glFramebufferTexture2D` callbacks; it does not trace other framebuffer operations such as invalidation.

The probe writes the new capture to an owned temporary directory and compares it with the pinned fixture after the native assertions succeed. `target.rgba.zlib` contains the 192 × 192 RGBA `glReadPixels` bytes after the draw run, SHA-256 `bf8ab3ad30331118e6f325e4cee8c2d0bca878cceab13fd096e573443640a051` uncompressed. The target attachment is R8; its readback alpha is not painted coverage, and null-data initial contents are host-dependent. Draw changes 72 bytes against the before readback; the skip control changes none. The manager canvas is substituted into a synthetic deferred message and initialization is explicit. This does not establish final object destruction or reference-count ownership, saved-page selection, device parity, or SVG/PDF parity. See v272 for the endpoint and factory controls.
