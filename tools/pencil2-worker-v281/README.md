# Pencil2 message through native AGLL queue

After the v219 preparation, run `python3 tools/pencil2-worker-v281/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v281/probe.py`. This extends v278: the same deferred Pencil2 message produced by the synthetic worker is placed in an initialized synthetic AGLL queue using native `enQueueMsg`, then native `RunTasks` dispatches its actual vtable Run and slot 8. The queue link identifies the original message, the observed Run/Update/Draw identities and subbitmap and matrix match v278, and the queue returns to its empty sentinel; a second drain invokes no slot 8. Slot 8 runs normally, but this does not establish message destruction or ownership semantics.

The host Mesa draw and skip controls reproduce the v278 322-byte and zero-byte changes and their frame hashes. The dispatcher still captures the message before this synthetic queue is populated; this is a controlled native queue round trip, not evidence that the application scheduled it through this queue. Locks and logging are stubbed, pointer exchange is single-threaded, and the queue owner is synthetic. Canvas injection, framebuffer binding for readback, actual threading, resource lifetime, saved-page scheduling and device behavior remain outside the evidence boundary. Runtime dependencies are not fully pinned.
