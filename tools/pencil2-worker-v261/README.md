# Native R8 bitmap copy probe

After v219 preparation, run `python3 tools/pencil2-worker-v261/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v261/probe.py`. This extends the pinned v255 synthetic harness with a host callback for `glCopyTexSubImage2D` and invokes `SPTextureBitmap::CopySubRegionFromBitmapRT` directly with two factory-created 192×192 bitmaps. Both allocations report `GL_R8`/`GL_RED`; the source factory explicitly receives zero stack layout arguments, while the destination stack values were not independently captured; `RGBA8888` is passed in the separate character-pointer position and does not select that format (see [v264](../pencil2-worker-v264/README.md)). It records the native entry, texture dispatch, host GL arguments, native cleanup tail and return. A host-created framebuffer attaches the destination texture for RGBA readback; it is complete and the readback error check returns zero. The normal and Draw-skipping destination readbacks match their source readbacks byte-for-byte, respectively SHA-256 `bf8ab3ad30331118e6f325e4cee8c2d0bca878cceab13fd096e573443640a051` and `5574536817c27b5cbfa5536e0235b9a5dd0a3e2705ba0dde2a1c79a5d7e879ee`. These are R8-to-R8 results, not an RGBA target.

The source readback is compared with the retained v255 fixture, and the Run, Update, and Draw hooks are checked before the copy. The probe restores the Unicorn CPU context and the previously captured read and draw framebuffer bindings, then deliberately exits with status 72; the wrapper requires this marker. The original v255 post-capture assertions do not run. An earlier attempt to continue after the nested calls exited with status 1 for an unverified reason. The return register value 2 is observed without assigning it a meaning; The destination object is checked at native entry, and the texture bound during the copy is the one attached for readback; the probe does not independently prove that texture belongs to the destination object. Native object destruction, queue lifetime, and production or saved-page invocation are unverified. The synthetic queue, manually substituted canvas, ARM emulation, host callbacks and unpinned Mesa limits from v255 apply. A final error check cannot rule out errors consumed by earlier calls.
