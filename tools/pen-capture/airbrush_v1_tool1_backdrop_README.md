# AirBrush V1 tool 1 opaque backdrop control

This control uses the reverse and zigzag inputs of `airbrush_v1_tool1_capture.py` with a native initial bitmap of RGBA (40, 90, 160, 255). The pinned Drawing libraries and local Mesa GLES execute the stroke over that bitmap. This is a synthetic host capture, not an Android-device or saved-note result. The receipt retains native post-draw frames, raw capture hashes, and RGBA absolute error totals.

The source-derived PNGs from `airbrush_v1_tool1_raster_diagnostic.patch` are generated independently of native frames as described in `airbrush_v1_tool1_README.md`. On the same opaque backdrop, Pillow source-over gives errors 46 and 326 for reverse and zigzag; PDF image transport rendered at 96 dpi gives MuPDF 54 and 471, and PDFium 56 and 461. This provides one backdrop control, not a guarantee for arbitrary scenes, multiple ordered objects, or other scales. Native frames are comparison targets only.

To replay, run `.venv/bin/python tools/pen-capture/airbrush_v1_tool1_backdrop_capture.py /tmp/airbrush-backdrop-new` with a nonexistent output directory. It validates the same runner and prerequisites as the original capture and checks both raw capture hashes. These local dependencies are not included in a clean checkout. To verify the retained frames and independent PNGs, run `PYTHONPATH=/tmp/pdfium-lib .venv/bin/python tools/pen-capture/airbrush_v1_tool1_backdrop_compare.py /path/to/generated/pngs`; the comparison pins PNG hashes, Pillow 12.1.1, PyMuPDF 1.28.2 and PDFium 150.0.7869.0. Adjust `PYTHONPATH` for the local PDFium installation.
