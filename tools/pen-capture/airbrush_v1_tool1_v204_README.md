# AirBrush V1 tool 1 additional controls

Three synthetic Model/Drawing captures extend the existing tool-1 diagnostic with a curved path (size 3.144), a turning path (6.5), and a vertical path (12), using two opaque colors and one translucent color. The retained receipt includes native source arrays, vectors and complete compressed frames. It is host Mesa evidence, not saved-note or Android-device parity. The capture script checks the same local runner and prerequisite hashes as the earlier tool-1 control; those local dependencies are not supplied in a clean checkout.

The isolated candidate patch adds tool 1 to the existing opt-in V1 profile. For these inputs, its sampled vector bytes match native in all three cases. At 256×256, public resvg RGBA absolute errors against native are 12, 0, and 4 respectively; generic errors are 5431, 13310, and 17423. Direct PDF comparisons are in `airbrush_v1_tool1_v204_pdf_receipt.json`, produced by PyMuPDF 1.28.2 and PDFium 150.0.7869.0 at 96 dpi. Both readers improve over generic for all three inputs. The earlier size-2.25 reverse control still regresses in MuPDF, so the candidate remains unintegrated; these cases do not establish a reliable size boundary.

To reproduce the native capture, run `.venv/bin/python tools/pen-capture/airbrush_v1_tool1_v204_capture.py /tmp/airbrush-v204-new`. The destination must not exist and its parent must exist. Before creating it, the script checks the local runner and the hash-pinned `airbrush_v1_curved_prerequisites.json` manifest from the earlier tool-1 receipt, then checks the resulting capture hashes. Those local dependencies are not included in a clean checkout.

Apply `airbrush_v1_tool1_v204_candidate.patch` with `git apply` to a clean checkout of this commit and create an empty PDF output directory. No earlier diagnostic patch or untracked Rust source is needed. This reproduction was verified against a clean archive of `417cab5c`. From the copy, run `CARGO_TARGET_DIR=/tmp/sdocx-agent-target CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 SDOCX_AIRBRUSH_MATRIX_DIR=/tmp/airbrush-v204-pdfs cargo test -p sdocx --lib --features pdf tool1_candidate_test -- --nocapture`. The test asserts the retained native vectors and both SVG error totals and writes PDFs exclusively. From the original checkout, run `PYTHONPATH=/tmp/pdfium-lib .venv/bin/python tools/pen-capture/airbrush_v1_tool1_v204_compare.py /tmp/airbrush-v204-pdfs`; it requires PyMuPDF 1.28.2 and pypdfium2 backed by PDFium 150.0.7869.0, and asserts all PDF hashes and measured errors. `/tmp/pdfium-lib` is the local location of that PDFium Python package; adjust `PYTHONPATH` for another installation. PDF hashes are source and dependency sensitive.
