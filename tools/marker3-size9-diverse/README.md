# Marker3 tool-1 size-9 controls

Three synthetic Model/Drawing strokes use reversal, crossing and short-turn trajectories with translucent red, opaque blue and translucent green. Each was captured at 1×, 2× and 4× using the explicit native vector bridge and host Mesa described in `../marker3-terminal/README.md`. Full caller records are compressed here; the fixture in `conformance/marker3-size9-diverse-native.json` retains the original input arrays and both complete Drawing and saved-redraw vectors. Each vector matches the Rust sampler bit for bit, and vectors and input records agree across all three scale captures. Frame bytes and SHA-256 digests are retained; these are not serialized-note or device captures.

The receipt compares public SVG (resvg) and direct PDF (MuPDF and PDFium), using the captured transparent native frame and its mathematical composite over #fcfcfc. All nine cases reduce aggregate error relative to the current generic fallback, both for default admitted output and the explicit scale option. The admitted outputs miss no native SVG support pixels; the generic fallback misses 102–8858. MuPDF error includes its paper conversion. This supports the size-9 admission; intermediate sizes, other trajectories, backgrounds, devices and notes remain extrapolations.

On the prepared capture host, `.venv/bin/python tools/marker3-size9-diverse/capture.py /tmp/marker3-size9-diverse` regenerates the nine frames and caller records. It requires the local inputs and incomplete dependency closure described in `../marker3-terminal/README.md`. Compare decompressed frames against `receipt.json` hashes. `PYTHON=.venv/bin/python PYTHONPATH=/tmp/sdocx-marker3-v133-readers tools/marker3-size9-diverse/replay.sh` builds and verifies all nine comparisons from a temporary archive of revision `9eaa8fc22d01d1564cc2a87c1b445e6147488460`, first with the original gate for generic fallback and then with its tool-1 size gate raised to 9; the shared target and offline lockfiles from `../marker3-size9-exploratory` were used. The comparator expects native RGBA, an export directory containing `generic`, `baseline`, and `profile` SVG/PDF files, and the retained case name. It uses the reader versions in the receipt. These scripts and hashes do not pin the complete build or reader dependency closure.
