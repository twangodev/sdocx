# Pencil2 explicit Draw matrix controls

Run `python3 tools/pencil2-worker-v244/probe.py` and `PENCIL_RAW=1 python3 tools/pencil2-worker-v244/probe.py` to verify the two retained receipts; `--write-receipt` updates the selected receipt. The adapter pins its three direct parents, which pin their own native dependencies. Each run independently repeats the v243 synthetic worker and explicit renderer initialization, update and draw. Both assert 84 AddPoint calls, the same selected renderer through update and draw, the observed Matrix3, transparent prior, and zero final GL error. Host EGL, GLES, Mesa and transitive libraries are unpinned; identical geometry bytes were not independently asserted.

The raw control expands the observed Matrix3 directly into a 4x4 Draw argument; the product control passes the native canvas getter's projection-times-model result. Both capture and assert the actual Draw argument and the `glUniformMatrix4fv` payload. The raw control paints 322 nonzero bytes. The product control paints none: its uploaded X and Y scales are approximately 1/9216, with translation approximately (-1.00977, -1.00944). The raw control uploads scales (1/96, -1/96) and translation (-0.9375, 0.90625). Thus this explicit RTV4 call applies another projection to the already projected canvas product. The resulting geometry is compressed near or beyond the lower-left clip edge; the specific roles of clipping and subpixel coverage are not isolated.

This is an adapter intervention on a synthetic queue and framebuffer, not a demonstrated production renderer handoff or device capture. The raw and product cases are independent executions, not successive calls on one live renderer. The screen bitmap, dimensions, orientation and model adapter are synthetic; normal scheduling and saved-page behavior remain open.
