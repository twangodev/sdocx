# Factory probe texture uploads

Run `python3 tools/pencil2-worker-v257/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v257/probe.py` after the v219 runtime preparation. This is the v256 format-intervention probe with `glTexSubImage2D` added to its captured call list. It asserts the ordered instrumented GL calls against the v257 state receipt and the drawn frame against the v256 fixture.

The 150×150 and 100×300 RGBA textures initially allocated with null data each receive a full-size RGBA upload. The respective guest-memory upload SHA-256 values are `6eb2dcce1a14653fb945de5eb446b8e706f9d02d86f74277a3146c08d0e6ea7e` and `743dc88582b5fe222d0375807c56be7ef4b03ee878d77f1bbe1e6f3b929558db`. The calls show supplied data, not that the shader sampled it correctly; GL errors could have been consumed by intervening calls. The factory target is still an RGBA8 intervention, and the synthetic canvas and host limitations in v255 and v256 remain. This does not establish Rust, SVG, PDF, saved-page or device parity.

`python3 tools/pencil2-worker-v257/compare.py` runs the current public Rust canvas with the v219 native Model setter baseline: points (0,0), (10,0), (20,0), (30,10); pressure 0.5; size 2; black; explicit Pencil2 V14, translated (6,9). The transparent prior and 192×192 output match the dimensions of the v256 intervention. The Rust grain calculation produces (6,9). Against the retained RGBA8 intervention's alpha, Rust has 88 nonzero pixels versus 87 native, with 79 differing pixels, maximum absolute difference 85 and total absolute difference 1616. Rust's bottom-row-first output SHA-256 is `ab531e16e25ba3efbca1a265dfa84f31779e7f45cc8918f31065f40093bb13d2` for this checkout. The R8 attachment's red channel is not equivalent to the intervened RGBA alpha; comparison with Rust alpha gives 88 differing pixels, maximum difference 155 and total difference 4941.

This is a diagnostic comparison of actual Rust output and the retained host capture, not evidence of equivalent native factory composition: the native message matrix, factory attachment format, projection and grain state have not all been established as equivalent to the Rust canvas setup. The native target is synthetic, and a mismatch does not locate its cause. Cargo runs offline with the shared agent target; the Rust hash and differences may change with the checkout.

The extended native call trace identifies a material setup difference: the native draw uploads grain uniform `(6,183)`, while the Rust helper given its current projection and translation computes `(6,9)`. The native draw matrix has a negative Y scale and Y translation 183; its recorded shader matrix maps the source origin to top-left position (6,9). The native blend factors are source alpha / one-minus-source-alpha for RGB and one / one-minus-source-alpha for alpha. These observations do not by themselves establish that supplying the raw uniform to the Rust API reproduces the native coordinate convention. As a diagnostic, `PENCIL_NATIVE_GRAIN=1 python3 tools/pencil2-worker-v257/compare.py` supplies `(6,183)` directly: 84 Rust alpha pixels are nonzero, 84 pixels differ, maximum difference 127 and total difference 2894. Therefore this substitution alone does not reconcile the frames. The unresolved contract is how native projection, Y inversion, grain coordinates and the R8 factory attachment are meant to compose with the public canvas coordinate system.

The probe asserts the complete ordered selection of 85 draw and 65 no-draw GL calls in `state-receipt.json`, including texture uploads and bindings, sampler and texture parameters, program use, blend state, active texture, scalar and vector uniforms, and the matrix uniform. This captures the instrumented calls in this harness; it does not claim an exhaustive GL error history or uninstrumented state.
