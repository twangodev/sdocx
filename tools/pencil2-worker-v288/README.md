# Pencil2 constructed wrapper and guard control

Run `python3 tools/pencil2-worker-v288/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v288/probe.py` after v219 preparation. This extends v287. The native `ObjectAsyncDrawing` constructor creates the separate wrapper and its two critical sections; the native `CriticalSection` constructor initializes the synthetic worker object's section at `async_obj+16`. The wrapper's initialized byte and renderer/drawing fields are set by the harness to bypass lazy initialization with a null context and retain v241's fabricated renderer. The request list is still transplanted into the singleton and the queue is explicitly drained.

The Drawing submission loads its guard pointer from wrapper offset 32 (RVA `0x799ac`). The constructor allocates separate critical sections at offsets 32 and 40 (RVA `0x7973c`); Base's critical-section constructor allocates mutex storage (RVA `0x99b38`). The lock/unlock callbacks bridge each observed nonzero guest address to a host Python `RLock`, created on first lock; the probe asserts balanced nested calls and matching guard identities. This bridge does not implement guest mutex initialization, destruction, attributes, contention, or scheduling, and these single-threaded captures do not establish real application synchronization. Other synchronization hooks and native queue interventions remain as in v287.

Both controls assert five native producer submissions and FIFO execution, original manager canvas and attachment, identities and matrices. The draw frame matches the v256 fixture SHA-256 `a0230ba18bf716851b4079facb415b265ade62b80ef28bbfcaa0b1853776672e`; skipping Draw produces SHA-256 `8123c216413f82bbaa0339c27a43d9822c2a043e20662b27c97874429b996e9a`. These are emulated native code with host Mesa and fabricated objects, not device or real scheduling evidence.
