# StraightMarker tool-1 4× host controls

Four synthetic `StraightMarker` tool-1 inputs with literal `5;` were captured using native Drawing and the explicit same-vector RTV1 host bridge at 4× on 512×512 Mesa RGBA8. Widths 4, 6 and 8, phases 0, 0.5 and 0.25 output pixels, opaque/translucent colors, and short, fractional and crossing paths match the earlier Marker3 native vectors and frames byte for byte. `native.json` records input float bits, factory selection, source/library hashes, and frame identities; `verify.py` checks these against the retained Marker3 controls. Native capture is `.venv/bin/python tools/marker3-tool1-scale4-alias/capture.py OUTPUT`, followed by `.venv/bin/python tools/marker3-tool1-scale4-alias/verify.py OUTPUT NEW_RECEIPT.json` (choose a new receipt path).

The historical public-export experiment used the same StraightMarker inputs with default and 4× options. Each case receipt compares resvg, MuPDF and PDFium with its newly captured transparent native frame; the PDF reference was mathematically composited over #fcfcfc. All three readers reduced aggregate error for all four cases, with no missing native SVG support pixels. MuPDF totals include a reader paper difference. The exporter and comparator have been retired; receipts retain their measurements and reader versions.

These are synthetic host controls, not serialized-note, arbitrary-input, native opaque-backdrop, transform, or device parity. Intermediate widths, empty settings, and other paths, colors and phases extrapolate from the controls; empty settings matched literal `5;` in the earlier 2× alias capture. The native bridge rejoins Drawing's captured vector after it clears its slots.
