# StraightMarker tool-1 4× host controls

Four synthetic `StraightMarker` tool-1 inputs with literal `5;` were captured using native Drawing and the explicit same-vector RTV1 host bridge at 4× on 512×512 Mesa RGBA8. Widths 4, 6 and 8, phases 0, 0.5 and 0.25 output pixels, opaque/translucent colors, and short, fractional and crossing paths match the earlier Marker3 native vectors and frames byte for byte. `native.json` records input float bits, factory selection, source/library hashes, and frame identities; `verify.py` checks these against the retained Marker3 controls. Native capture is `.venv/bin/python tools/marker3-tool1-scale4-alias/capture.py OUTPUT`, followed by `verify.py OUTPUT native.json`.

`export.rs` uses the same StraightMarker inputs and generates paired public SVG and direct PDF with the default and 4× options. Each case receipt compares resvg, MuPDF and PDFium with its newly captured transparent native frame; the PDF reference is mathematically composited over #fcfcfc. All three readers reduce aggregate error for all four cases, with no missing native SVG support pixels. MuPDF totals include a reader paper difference. The exports can be built as a temporary Rust harness using the workspace `sdocx` crate with `serde,pdf`, then compared with `compare.py FRAME EXPORT_DIRECTORY RECEIPT` using the reader versions in the receipts.

These are synthetic host controls, not serialized-note, arbitrary-input, native opaque-backdrop, transform, or device parity. Intermediate widths, empty settings, and other paths, colors and phases extrapolate from the controls; empty settings matched literal `5;` in the earlier 2× alias capture. The native bridge rejoins Drawing's captured vector after it clears its slots.
