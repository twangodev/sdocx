# Queued drawable initialization

After the v219 preparation, run `python3 tools/pencil2-worker-v278/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v278/probe.py`. This follows v277's synthetic worker and original manager-canvas handoff, but removes the explicit drawable Init call. An entry hook installed before the worker observes exactly one native `Pencil2StrokeDrawableRTV4::Init()` on the selected drawable, with return address `0x20001020` at Init entry, in the synthetic queue dispatcher. The deferred render message is dispatched by reading its native vtable Run slot; the host still explicitly drains this one message. Native Run calls Update and Draw with the original canvas's subbitmap and the asserted matrix.

On this host the draw and skip controls reproduce the v277 frame and empty-frame hashes and change 322 and zero bytes respectively. The probe still binds the framebuffer for the first readback. Canvas factory injection, synthetic queue scheduling, host GLES, bitmap lifetime and destruction, saved-page traversal, and device behavior remain outside the established boundary. The frame is the same fixture used by the bounded alpha-only export comparisons in v274; this experiment adds lifecycle evidence, not a new export or saved-note comparison. Transitive runtime dependencies are not fully pinned.
