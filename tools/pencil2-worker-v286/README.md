# Pencil2 critical-section body diagnostic

Run `python3 tools/pencil2-worker-v286/probe.py` and `PENCIL_SKIP_DRAW=1 python3 tools/pencil2-worker-v286/probe.py` after the v219 preparation. This extends v285 by removing both inherited symbol callbacks for the `AutoCriticalSection` constructor taking source location and its destructor. It traces the emulated `pthread_mutex_lock` and `pthread_mutex_unlock` callback arguments; both remain success-returning stubs. The draw and skip retain the v285 framebuffer and FIFO assertions (322 changed bytes and zero respectively).

Both runs recorded 18 lock and 18 unlock callbacks at the capture point, including two calls of each with a null argument and a lock/unlock pair with different addresses. Those observations expose an unresolved host or synthetic-context boundary; equal totals do not establish balanced ownership, correct synchronization, or valid mutex objects. The v285 PLT entry observation did not establish destructor-body execution: the v241-derived harness intercepts the destructor symbol. Removing only that interception caused an unmapped read while the paired constructor was still stubbed. Removing both lets this bounded capture finish; it does not establish a valid full application lifecycle. No real pthread, concurrency, teardown, native free, or new Rust/SVG/PDF comparison is claimed. Other v285 limitations apply.
