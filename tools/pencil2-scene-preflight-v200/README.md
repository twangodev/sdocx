# Pencil2 aggregate SVG staging experiment

Run `tools/pencil2-scene-preflight-v200/run.sh`. This uses the v199 pinned clean archive and source-generated two-stroke inputs, with a separate probe. The Rust probe stages both stroke fragments, checks their aggregate rectangle count and exact SVG byte length with checked arithmetic, then selects the staged scene only after both limits pass. It exercises just below, exactly at, and above each aggregate boundary and verifies the fallback destination remains byte-for-byte unchanged on rejection. The original v198 native prefix comparison and v199 ordered/reversed scene comparison also run. The empty scene also exercises its byte budget below, at, and above the prefix and closing-tag size. The runner pins the probe and helper hashes. A second Python check renders the exact bytes accepted by Rust, compares them with the original source-generated scene and verifies fallback with the actual generic SVG. The v198 native comparison is therefore also a comparison of those accepted bytes. Python optimization is rejected because the checks use assertions.

The measured Rust scene has 6,113 rectangles and 608,273 bytes. This is a staging experiment, not a production resource limit: source stamp frames and individual strings have already been allocated before admission, the fallback selection is local to the harness, and neither total document resources nor PDF object mutation are covered. The v199 PDF form adds resources before its stream check, so this experiment does not establish PDF atomic fallback. The only inputs are the two hash-gated host-Mesa strokes and their one blue-background scene; existing native and reader discrepancies remain. It must not be enabled as a public rendering option on this evidence.
