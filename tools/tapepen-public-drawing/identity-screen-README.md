# TapePen identity-matrix display controls

These synthetic native host-Mesa Drawing controls hold the input, identity matrix and 512×512 bitmap fixed while changing IDisplay from 256×256 to 512×512. The complete native RGBA frames differ by 15,115 absolute channel levels across 423 channels (maximum 131). The 256-display frame's 256×256 crop is byte-identical to the original v173 1× frame, which used a 256×256 bitmap. This establishes a display-profile effect in this control, without establishing its full cause or device or saved-document parity.

A source-generated v173 mask using the existing `tape_size_level` and `tape_aa_width` functions, exported through the existing pixel-grid vector diagnostic, reduces the 512-display crop's premultiplied RGBA L1 error from 15,132 with 256-display AA to 11,123 with 512-display AA, with respective maximum errors 131 and 113. The 512-display adjustment alone does not reproduce the native frame. These are SVG diagnostic measurements, not paired native PDF tests, and are insufficient to justify a production export profile. resvg 0.45.1 and Pillow premultiplication were used.

Both wrappers require the pinned local prerequisites described in `fixed-screen-2x-README.md`. Capture with `UV_CACHE_DIR=/tmp/sdocx-uv-cache uv run --offline --with unicorn==2.1.4 python tools/tapepen-public-drawing/identity-screen-256.py --run --shape64 --size12 > /tmp/tape-identity-256.log`, and repeat with `identity-screen-512.py`. Run the corresponding `verify-identity-screen-256.py` and `verify-identity-screen-512.py` with each log; they check input, native hashes, profile, framebuffer attachment, retained frame, and the reported frame difference. The wrappers assert native screen resolution calls during capture. Run `tools/tapepen-public-drawing/identity-screen-replay.sh` from this checkout to reproduce both source-mask tests and hash-bound SVG comparisons. The script uses a disposable source copy, the shared agent Cargo target, offline dependencies, resvg 0.45.1 and Pillow via the offline uv cache, or an existing interpreter selected with `SDOCX_TAPE_PYTHON=/absolute/path/to/python`. It checks the resulting SVG hashes and exact comparison metrics before removing its temporary files. The receipt records the source-mask hashes as additional evidence.

The source replay also requires the retained `v173-source-mask.patch`, `v173-vector.py`, and `pattern01-native.rgba.zlib`; the native verifiers use `v173-1x-frame.rgba.zlib` as the original 1× reference. These compact dependencies are included. Native capture prerequisites listed above remain local-only. Validation used fresh captures for both displays and a source replay from a clean committed source tree with `SDOCX_TAPE_PYTHON=/home/jding/RustroverProjects/sdocx/.venv/bin/python` (Pillow 12.1.1).

A fresh paired capture's [native uniform comparison](identity-screen-state-receipt.json) identifies two additional display-dependent inputs. At display 256 versus 512, `uVertexHalfExtent` changes from approximately (1.68, 6.72) to (1.77545, 7.10182), and `patternSize` changes from (64, 64) to (128, 128). `uEllipseRadii` remains (1.5, 6), `grainOffset` remains (77, 59), and the observed position and shadow offsets are unchanged. The earlier AA-only diagnostic held the quad extent and pattern size fixed, so it did not model these native state changes. Their presence explains why that approximation is incomplete; it does not quantify each contribution or prove the complete pattern/composite mapping. The separate `identity-screen-state.py` script checks both capture verifiers and hashes each native uniform payload before comparing them. The compact compressed capture logs are retained as `identity-screen-state-256.log.gz` and `identity-screen-state-512.log.gz`; decompress them to temporary paths and pass those paths to the script. The script pins those exact log hashes, checks ordered program uses, actual draw program, uniform locations and payloads, and records the selected provenance. A new capture has its own log identity and requires a separately reviewed receipt. No public export dispatch is warranted by this bounded state comparison.
